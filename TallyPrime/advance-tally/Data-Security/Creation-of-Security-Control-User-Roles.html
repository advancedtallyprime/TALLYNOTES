1. Core Concept

User Roles define what different categories of employees can and cannot do in TallyPrime. Rather than granting users blanket access, administrators define explicit Allow and Disallow rules for each functional area.

2. Built-in vs. Custom User Roles

  • Built-in Roles: Owner (complete access except user administration) and Data Entry (voucher entry only).
  • Custom Roles: Created to reflect exact company hierarchy: Sales Executive, Billing Operator, Inventory Manager, Tax Consultant.

3. Step-by-Step Creation of a Custom User Role

Navigation: Gateway of Tally → Press Alt + K → User Roles.

Example: Create a role named Billing Operator who can create Sales invoices, but CANNOT view Balance Sheet, P&L, Bank ledgers, or backdated vouchers.

Field / Column Setting Functional Meaning
Security Level Billing Operator Name of the custom security role.
Use Basic Facilities of Data Entry Inherits basic data-entry templates.
Days allowed for backdated vouchers 0 Days (or 2 Days) Operator cannot tamper with vouchers from past dates!
Disallow the following Facilities Full Access → Balance Sheet
Full Access → Profit & Loss A/c
Full Access → Bank Accounts		 Hides confidential company wealth and bank accounts.
Allow the following Facilities Create/Alter → Sales Vouchers
Create/Alter → Receipt Vouchers		 Enables daily customer invoicing and cash collections.

4. Interview Questions & Answers

Q1. How can an administrator prevent sales clerks from modifying invoices created last month?

Ans: In the User Role configuration, set Days allowed for backdated vouchers to 0 (or 1). Any attempt to save or modify an entry with an older date will be blocked by TallyPrime.

Q2. Can a user role be restricted from printing or exporting financial reports?

Ans: Yes. Under Disallow rules, set Print and Export facilities to Disallowed for the specific report group.
